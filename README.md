# 交通时空大数据分析与可视化 · 前端

沈阳市城市交通抽样数据的分析结果展示页。

**实训班小组项目**，数据清洗、出行判定与统计部分由组内其他成员完成，**本人负责前端展示层**。

---

## 一、项目背景

一份 20,000 行的手机信令抽样数据（202 位用户、2018 年 10 月），目标是回答三个业务问题：这些人什么时候出门、用什么方式出门、出门去干什么。

分析侧用 Python 跑完清洗、出行 / 驻留判定（速度粗筛 + 逐用户 KMeans + 距离时长精判）和结果统计，最终产出 9 项结论；前端负责把这些结论组织成一个能读、能看的页面。

## 二、我做了什么

- 用 Vue 3 + Vite 从零搭起工程骨架，按「清洗 → 判定 → 结果」三段式组织页面结构，对应分析链路本身
- 抽出 `FigureCard` 组件承载单个分析结论（图 + 标题 + 说明），页面主体靠数据驱动渲染，不写死 DOM
- 页面顶部放四个关键指标（原始记录 / 有效记录 / 用户数 / 出行点占比），进页面先看到规模
- **第二阶段补上了数据直连渲染**：不再只展示分析阶段导出的 PNG，改为浏览器直接 `fetch` 结构化结果，在组件内完成字段聚合，再交给 ECharts 绘制三张图——出行方式环形图、出行目的柱状图、24 小时出行量折线图
- ECharts 按需注册，只引入实际用到的三种图表与三个组件，构建产物从 1,188 kB 降到 623 kB
- 右下角返回顶部按钮：滚动超过一屏后淡入，点击平滑回顶

## 三、页面结构

| 区块 | 内容 |
| --- | --- |
| 一、数据清洗 | 24 小时记录分布、用户维度概览 |
| 二、出行判定 | 移动速度分布、KMeans 肘部曲线、驻留/出行占比 |
| 三、结果分析 | 出行目的、出行方式、分时人流热力图、全时段人流分布 |
| 四、前端实时渲染 | 出行方式环形图、出行目的柱状图、24 小时出行量折线图（ECharts，数据直连） |

前三块是分析阶段导出的静态图，第四块是浏览器端实时聚合渲染——同一个结论，两种呈现方式放在同一页里对照。

## 四、技术栈

| 层 | 选型 |
| --- | --- |
| 框架 | Vue 3.5（`<script setup>` 组合式 API） |
| 构建 | Vite 8.3 |
| 图表 | ECharts 5（按需引入：Pie / Bar / Line + Tooltip / Legend / Grid） |
| 样式 | 原生 CSS（scoped、Grid、媒体查询） |
| 数据 | 静态 JSON（`public/data`），浏览器端聚合 |

未引入路由与状态管理——单页项目，不需要。

## 五、本地运行

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 产物在 dist/
```

要求 Node 18+。

## 六、数据说明

`public/data/` 下是分析阶段导出的结构化结果，共 9 个文件、约 19.8 MB：

| 文件 | 行数 | 用途 |
| --- | --- | --- |
| `cleaned_data.json` | 19,778 | 清洗后的原始记录 |
| `mode_result.json` | 9,081 | 出行记录及其方式判定 |
| `purpose_result.json` | 10,310 | 驻留记录及其目的判定 |
| `heatmap_result.json` | 7,460 | 分时网格热度 |
| `stage1_travel_points.json` | 19,778 | 阶段1 速度判定结果 |
| `stage2_cluster.json` | — | 阶段2 聚类结果 |
| `stage2_sse_curve.json` | — | 阶段2 选参曲线 |
| `manifest.json` | — | 数据清单 |

数据为教学用抽样样本，已脱敏处理。

## 七、已知限制

- **没有后端接口**：数据是构建期就放在 `public` 下的静态 JSON，页面不经过服务端
- **热力图仍是静态 PNG**：`heatmap_result.json` 虽有经纬网格数据，但前端尚未接成 ECharts 地理热力图
- **只做了栅格降级**：窗口变窄时卡片自动堆叠，但没有针对移动端重新设计交互
- 项目已停止开发，当前状态为「分析结论可完整浏览，前端展示层可独立运行」
